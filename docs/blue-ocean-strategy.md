# ブルーオーシャン戦略：AIエージェント／LLM の第三者品質保証

## なぜここを攻めるのか

モデル企業ベリサーブの強みは「**独立した第三者によるソフトウェア品質保証**」。
いま、その強みが効く一方で**まだ競合がほとんどいない**市場が生まれています。

- AI／LLM／自律エージェントの社会実装が爆発的に拡大している。
- しかし「**そのAIは本当に正しく・安全に・一貫して動くのか**」を、開発元から独立した第三者が体系的に検証する手段は未成熟。
- 従来のソフトテスト（決定的・合否判定）は、確率的で非決定的なAIにはそのまま通用しない → **新しい検証工学が要る**。
- 規制・AIガバナンス・監査要求が世界的に強まり、「第三者による評価・保証」への**追い風**が吹いている。

ここに、当社の検証DNA（テスト設計・メトリクス・独立性・説明責任）を移植する。
**「AIがAIを検証する」**——本リポジトリ自体が、AIエージェント組織でAIを検証する実証でもあります。

## 戦略キャンバス（ERRC）

| 取り組み | 内容 |
|---|---|
| **取り除く (Eliminate)** | 「動けばOK」という合否二値の発想／属人的な目視確認 |
| **減らす (Reduce)** | 一度きりの手動評価への依存／ベンダー自己申告の品質主張 |
| **増やす (Raise)** | 再現可能性・統計的厳密さ・エビデンス・独立性・説明責任 |
| **創る (Create)** | AIエージェント特有の評価軸（ツール選択/計画/暴走/安全性）／回帰検出／第三者の「AI品質保証書」 |

## 価値曲線（差別化の軸）
**独立性 × 再現可能な評価 × 説明責任（エビデンス）** の3点で、開発元の内製評価や汎用ベンチマークと差別化する。

## 提供価値（顧客の便益）
- AI導入の**リスクを第三者の目で可視化・低減**できる（経営・コンプラの説明責任を果たせる）。
- モデル/プロンプト更新時の**品質劣化（回帰）を検出**できる。
- 規制・監査・調達要件に対し、**独立した検証エビデンス**を提示できる。

## サービスライン（売り物）
1. **AIエージェント/LLM 第三者検証**（スポット）：評価設計→実行→検証レポート納品（`/ai-qa`、`products/ai-agent-qa/`）
2. **AI品質 継続モニタリング**（ストック）：回帰検出を定期実行する月額サービス（高NRR）
3. **AI品質保証 体制構築コンサル／研修**：顧客が自走できるAI-QA体制づくり（`qa-consultant`）
4. **AI品質 標準・ツール**：評価フレーム/ツールの提供（QualityForward/GIHOZ のAI版という発展）

## 評価軸（当社標準フレーム＝差別化の中身）
タスク達成度 / 事実性（ハルシネーション）/ 堅牢性 / 安全性（インジェクション・漏えい）/ 一貫性 / エージェント特有（ツール選択・計画・暴走・コスト）/ 公平性 / コンプライアンス。
詳細な測定法は `products/ai-agent-qa/methodology.md`、研究の担い手は `ai-quality-researcher`。

## 市場仮説（要検証）
> 数値は戦略議論用の仮説。`corp-strategy` と `finance` が `/new-service`・`/board-meeting` で精緻化する。

- ドライバー：企業のAI本番導入比率の上昇 × 規制対応 × 失敗事故の顕在化。
- セグメント：金融・医療・自動車・公共など**説明責任が重い領域**から先行需要。
- 収益構造：スポット検証で入り、継続モニタリング（ストック）と体制構築（コンサル）へ広げて**LTVと粗利率を最大化**。

## リスクと撤退条件
- リスク：評価方法論の標準が定まらない／LLM-judge の信頼性／価格感度。
- 対応：人手較正・統計的厳密さで信頼を担保、標準化をリード（marketing/研究）。
- 撤退条件：一定期間でPoC受注が閾値に満たない場合は投資縮小（`/board-meeting` で判断）。
