# 収益モデル：どう稼ぐか

「組織が実際に稼げる」ことを担保するため、価値（成果物）と対価（収益）の流れを定義します。
数値はすべて**戦略議論用の仮説**で、`finance` が案件ごとに精緻化します。

## 稼ぎの全体像

```
顧客の品質リスク ──(独立検証で引き受け)──▶ 検証成果物（証跡つき） ──▶ 対価
        既存：ソフトウェア第三者検証（安定収益・キャッシュ源）
        新規：AIエージェント/LLM 第三者検証（高成長・ブルーオーシャン）
            └─ スポット → 継続モニタリング(ストック) → コンサル/研修 で LTV 拡大
```

## 収益の柱

| 収益タイプ | 内容 | 特性 | 主担当 |
|---|---|---|---|
| フロー（スポット） | 案件単位の検証（テスト/AI検証） | 受注変動あり・入口 | sales, qa-architect, ai-eval-engineer |
| ストック（継続） | 継続モニタリング・回帰検出の月額 | 高NRR・予測可能 | ai-eval-engineer, qa-architect |
| コンサル/教育 | プロセス改善・内製化・研修 | 高粗利・関係深化 | qa-consultant |
| プロダクト/標準 | テスト管理/設計ツール・評価フレーム | スケール・低限界費用 | cto, ai-quality-researcher |

## 案件採算の標準ロジック（`finance` が実行）

```
1) 必要工数（qa-architect の根拠）× ロール別単価        = 直接原価
2) ＋ ツール/環境/管理費（間接費率を乗算）              = 総原価
3) 目標粗利率（基準 35〜45%）から見積価格を逆算
4) 価値ベース上限（顧客が得るリスク低減効果）と照合
5) 粗利率がしきい値未満 → 警告し、スコープ/単価/体制を見直し
```

### 試算例（AIチャットボットのスポット検証 / 仮）
| 項目 | 値（仮説） |
|---|---|
| 工数 | 評価設計5人日＋実装/実行8人日＋レビュー2人日＝15人日 |
| 平均単価 | 8万円/人日 |
| 直接原価 | 120万円 |
| 間接費(20%) | 24万円 → 総原価 144万円 |
| 見積価格（粗利率40%目標） | 約240万円 |
| 粗利 | 約96万円（採算OK） |

> ↑ これは `/win-deal` を回すと `qa-architect`→`finance` が実際にこの形で算出します。

## KPI ツリー（`corp-strategy` 設計 / `finance` 管理）

```
企業価値
└─ 売上 = 受注件数 × 平均単価 × リピート率
   ├─ 受注件数 ← リード数(marketing) × 商談化率(sales) × 受注率(qa-architect の提案品質)
   ├─ 平均単価 ← サービスミックス（スポット→ストック→コンサルへの引き上げ）
   └─ リピート率/NRR ← 検証品質(デリバリー) × 継続モニタリング比率
└─ 粗利率 ← 採算規律(finance) × 自動化による原価低減(test-automation/ai-eval)
└─ 成長性 ← ブルーオーシャン売上比率（AI検証）
```

## 「稼げる」を成立させる3条件
1. **品質が高い**：独立・再現可能・エビデンスつき → 単価が取れ、リピートされる（デリバリー部門）。
2. **採算規律がある**：粗利率しきい値を割る仕事は受けない／代替案を出す（finance）。
3. **新市場で先行する**：競合の薄いAI第三者検証で高単価・高成長（AI品質本部＋marketing）。

## まずは動かす

- 稼ぎ頭を体験：`/ai-qa <AIの概要>` → 納品レポート生成
